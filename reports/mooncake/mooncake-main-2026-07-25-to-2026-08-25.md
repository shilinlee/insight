## 重点摘要

本月 Mooncake 主线围绕 **Store 高可用与多级存储生产化**、**TENT/Transfer Engine 新网络后端及可靠性**、**Reshard/PG 分布式模型能力**、**Python 结构化数据交换** 四条主线推进。

1. **Store HA 从恢复功能走向可控的一致性协议**：standby snapshot 增加有界捕获、分块 artifact、batch OpLog snapshot metadata、producer view fencing 与显式错误；同时补齐 promotion、跨 shard 重复、恢复副本驱逐和 allocator gap 等边界，提升故障切换的确定性。
2. **本地盘与对象存储形成统一的多级后端方向**：新增 DFS/POSIX replica、NVMe KV local-disk backend、object-storage adapter、固定 SSD→GPU restore、LOCAL_DISK 半卸载，以及共享盘物理容量上限。Store 的磁盘能力正从单一 SSD offload 扩展为多后端、可恢复、可治理的数据层。
3. **TENT/Transfer Engine 拓展多 rail 与异构互联**：新增 MPComm RDMA-native multi-rail、FlagCX、MUSA IPC、原生 UB/URMA、IBGDA GPU-VA/DMA-BUF 路径和 RDMA two-sided 控制通知；Ascend direct 自动探测与 NVLink wheel 交付也进一步完善。
4. **数据路径继续减少拷贝和调度开销**：TCP 启用连接池并使用有界 per-peer lanes，TENT TCP send/receive 减少复制，scatter transfer 合并任务，Store 同节点 tensor put、同进程 GPU read 绕过 staging，io_uring bucket read 批量化。
5. **Reshard 与 PG 开始形成面向弹性模型服务的独立能力**：Reshard 新增资源/模型权重 manifest、N 维逻辑权重迁移规划、模块测试门禁；PG 支持 inplace rejoin 和 P2P 恢复，EP 解耦 Torch C++ API 并增加 incast benchmark。
6. **Python 数据接口和打包体系继续产品化**：新增 ranged multi-buffer put/get session API、DataProto fragmented-rollout catalog、jagged NestedTensor、typed-ragged layout 和 native fast-copy PUT；构建侧引入 scikit-build-core 基础并简化 wheel workflow。

## 新特性与产品能力

### 1. Store HA snapshot 与 durable OpLog 协议成型

本期 HA 改动把 snapshot、OpLog 和主备切换连接成更完整的恢复链路。有界 standby snapshot capture 避免快照无限占用资源，chunked artifact writer 支持大快照分块落盘；batch OpLog snapshot metadata 和 durable prefix 中的 producer view，使恢复端能够识别数据所属生产者视图。batch writer 会按 producer view 隔离，ordered writer 失败进入终态，HA promotion 也允许在无 OpLog 的场景继续进行。

围绕这套协议还补齐了跨 shard standby duplicate 拒绝、supervisor view 传播验证、显式 restore error、不可读恢复副本防驱逐、snapshot allocator gap 回收和 remount 快速路径。总体上，Store HA 正由“能够备份与恢复”转向具有代际隔离、故障显式化和资源边界的生产协议。

### 2. 多级存储后端与副本管理扩展

Store 新增 DFS replica 的 POSIX backend、NVMe KV local disk backend 和 object storage adapter abstraction，为文件系统、NVMe KV 与对象存储提供更清晰的扩展入口。LOCAL_DISK segment 增加 unmount half，offload RPC 遵循连接超时；SSD→GPU restore 支持 pinned buffer，POSIX restore 避免 direct-I/O padding，shared-disk bucket 可按真实物理字节设置上限。

副本策略方面，新增 dynamic hot replica fanout，可根据热点动态扩大副本；固定 soft pin lifecycle 为需要保留的数据提供更明确的生命周期。与此同时，promotion-on-hit starvation/retry loss、SSD carryover key 重复、MoveEnd 引用泄漏及 Put/Upsert 与 promotion 竞态得到修复，表明副本状态机和分层缓存之间的交互是当前稳定性重点。

### 3. 新传输后端与异构设备覆盖

TENT 加入 UCL MPComm transport，以 RDMA-native multi-rail 方式利用多网卡；Transfer Engine 新增 FlagCX，TENT 建立原生 UB/URMA 资源管理基础，MUSA IPC 支持批量拷贝。IBGDA 增加 per-QP GPU VA 控制路径与 DMA-BUF Device API；RDMA two-sided transport 增加控制面通知 channel、frame codec 和 sender credit ledger。

异构平台也更深入集成：Ascend direct 可通过 capability 自动识别 AutoConnect 与 client-server 模式，Ascend agent-mode Store pool 可分摊到多个 engine；x86_64 CUDA wheel 开始交付节点内 NVLink transport。相比单纯新增设备枚举，这些提交覆盖资源管理、控制面、数据面与发布物，说明新后端正逐步进入可使用状态。

### 4. Reshard、PG 与 EP 的弹性能力

Reshard 新增 resource/model-weight manifest contracts，以标准契约描述资源与权重；N-D logical weight transfer planner 可为多维切分权重生成迁移计划，并新增独立 module test gate。PG 支持 inplace rejoin 并修复 P2P recovery，为成员重入和通信恢复提供基础。

EP 将 native 实现从 Torch C++ API 解耦，降低框架版本耦合，同时增加带 incast routing pattern 的 dispatch/combine benchmark 和 ARM64 构建。这些变化共同指向训练/推理实例扩缩、权重重分布和通信组恢复等更完整的弹性服务场景。

### 5. Python 结构化数据交换继续扩展

Store 新增 ranged multi-buffer transfer 的 put/get session API，使调用方可分段操作多个 buffer。Wheel 增加 fragmented rollout data 的 DataProto catalog、jagged NestedTensor transfer、优化 typed-ragged rollout layout，并通过 native fast-copy PUT hot path 和 grouped structured-object writes 减少 Python 层组装开销。

这些能力更贴近 RL rollout、变长序列和复合对象传输。结构化对象不再局限于规则 tensor，而开始覆盖碎片化、ragged 与 nested 数据，同时保留多 buffer 分组和快拷贝路径。

## 性能优化与可扩展性

### 1. TCP、scatter 与 GPU 数据路径减少额外开销

TCP connection pool 默认开启，并通过有界 per-peer connection lanes 调度传输；session progress deadline 防止连接长期无进展。TENT 在 `sendData/onRecvData` 减少复制，scatter transfer 将任务分组，设备策略 mask 从每请求解析改为预先解析，RDMA endpoint 回收移出 Store lock。这些改动同时降低复制、锁竞争和每请求配置计算成本。

Store 在同节点 tensor put 和同进程 GPU read 中绕过 staging，structured-object 写入保留 grouped writes；typed-ragged 与 native fast-copy PUT 优化 Python 热路径。对 GPU 数据交换而言，这类路径缩短通常比单纯提高后台线程数更直接。

### 2. 磁盘读取、恢复与元数据规模优化

io_uring bucket read 改为批量提交，file-read worker pool 可配置；pinned SSD→GPU restore 减少分页内存带来的额外代价，POSIX restore 则去除不必要的 direct-I/O padding。无待恢复副本时，`ReMountSegment` 跳过全量 metadata scan；eviction cycle 后主动 shrink metadata maps，控制长期运行的内存占用。

tenant quota charge/release 改为 lock-free，dynamic hot replica fanout 则用额外副本承接热点。建议后续结合租户并发和热点迁移压测，确认 lock-free 计费的正确性以及 fanout 收敛策略不会放大容量压力。

### 3. 多 NIC、EFA 与 IBGDA 资源利用优化

TENT 支持自定义 NIC priority matrix 和原生 topology dump，RDMA 会跳过无法对目标 GPU 执行 GPUDirect DMA 的 NIC，并修正 fallback device rotation。EFA 根据 libfabric provider 推导 WR/CQ pacing depth，拆分跨 BufferDesc chunk 边界的传输，并绑定 loopback buffer 的正确设备。IBGDA per-QP GPU-VA 路径为 GPU 主导的数据面提供更细粒度控制。

这些优化提升了多 NIC 与异构拓扑下的选择精度，但也扩大了拓扑状态生命周期的风险；窗口末尾对 RailMonitor topology use-after-free 的修复说明，拓扑刷新和异步任务之间仍需重点验证。

## 稳定性、Bugfix 与生产化硬化

- **HA 与恢复一致性**：修复 snapshot/partial-unmount 测试竞态、跨 shard standby duplicate、producer view writer fencing、unreadable recovered replica eviction、HA durable-finalization 和 promotion-without-OpLog 等问题。
- **Store 副本与分层缓存**：修复 promotion-on-hit 饥饿与 retry 丢失、Put/Upsert completion 与 promotion 生命周期冲突、SSD carryover key 重复、offload 后 timestamp 未更新、MoveEnd 引用计数泄漏及 snapshot allocator gap。
- **TENT 生命周期与并发**：修复 RailMonitor topology use-after-free、ProxyManager stage-buffer map 竞态、晚到 completion 未 unpin、异步 staging cleanup、pending batch shutdown 无界等待、lazy-free sweep 提前停止及 transfer poll batch 泄漏。
- **RDMA/TCP/EFA 正确性**：修复 TCP endpoint refresh、RDMA reconnect storm、QP/控制回调注销、EFA chunk 边界、错误 NIC/GPU 组合，以及 `MC_IB_PORT=0` 导致全部 RNIC 禁用的问题。
- **GPU 与异构上下文**：修复 NVLink/MNNVL batch copy 未同步调用方 per-thread stream、DummyClient CUDA IPC readiness、EFA CUDA loopback device 绑定、MUSA compatibility macro 和 GPU-less host CUDA probe。
- **服务退出与诊断**：shutdown watcher 正确屏蔽/处理 SIGTERM、SIGINT，初始化阶段安装 handler，TCP session deadline 限制卡死；CTest 保留失败诊断，固定端口测试冲突和夜间环境隔离也得到改善。

## 易用性与文档

文档新增多租户部署指南、FakeTransport runtime test 机制、task manager replica 行为，并对 Python setup API、PyPI 包说明、PG 设计和 design/performance 导航进行整理。tebench 新增多 target 运行和即时带宽报告，TENT 可输出原生 NIC topology，帮助用户验证多 rail 选择与实时性能。

构建发布方面，引入 scikit-build-core Python 基础，简化 wheel workflow，并交付 x86_64 CUDA NVLink transport、CUDA 13 `sm103` 与 ARM64 EP 构建。YLT 改用 FetchContent，CMake target dependency 显式化，减少 submodule 和隐式构建顺序带来的环境差异。
